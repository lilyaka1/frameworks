# Отчёт по практической работе №9

**Проект:** «Система учёта API-интеграций»  
**Тема:** Анализ требований и планирование монолитного приложения

## Требования

### Функциональные

1. Пользователь просматривает сервисы, API и историю запросов.
2. Пользователь получает список интеграций через REST API.
3. Авторизованный оператор добавляет результат API-запроса.
4. Администратор управляет сервисами, ключами и пользователями.
5. Пользователь скачивает JSON-выгрузку интеграций.

### Нефункциональные

- REST-ответ возвращается в JSON и не раскрывает секреты.
- Некорректные данные получают HTTP 400, неавторизованные записи запрещены.
- Сервис имеет healthcheck и воспроизводимый запуск.
- При 1000 интеграций ответ должен укладываться в 1 секунду.

## Риски и масштабирование

Ключевые риски: утечка API-ключа, ошибочная production-конфигурация, рост
журнала запросов и отказ единственного экземпляра. Меры: переменные окружения,
маскирование секретов, CSRF/auth, резервное копирование и healthcheck.
При росте нагрузки SQLite заменяется PostgreSQL, кэш — Redis, архивы — object
storage, а приложение запускается несколькими экземплярами за reverse proxy.
